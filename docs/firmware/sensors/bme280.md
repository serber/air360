Temperature, humidity, and pressure sensor from Bosch.

## Transport

- I2C, bus 0 (SDA=GPIO8, SCL=GPIO9)
- Default address: `0x76`
- Valid addresses: `0x76`, `0x77` (configurable through the web UI)

## Initialization

1. Resolve bus pins via `context.i2c_bus_manager->resolvePins()`
2. Initialize the `bmp280_t` descriptor via `bmp280_init_desc()` (validates the I2C address), then set the 100 kHz clock and enable pull-ups on the embedded `i2c_dev` descriptor
3. Initialize the sensor via `bmp280_init()` with an explicit parameter set — the function resets the chip, validates the chip ID, and reads the calibration data:
   - Mode: `FORCED` (triggered on each poll)
   - Oversampling: x1 (`BMP280_ULTRA_LOW_POWER`) for temperature, humidity, and pressure
   - IIR filter: off (`BMP280_FILTER_OFF`)
   - Standby duration: 0.5 ms (irrelevant in forced mode)
4. Reject the chip if `device_.id != BME280_CHIP_ID` — the component also accepts the humidity-less BMP280, which this sensor slot does not support

## Polling

Each poll cycle:
1. Trigger a forced measurement via `bmp280_force_measurement()`
2. Wait for completion: up to five 10 ms delays, checking `bmp280_is_measuring()` after each (x1 oversampling finishes in under 10 ms; a sensor still busy after 50 ms reports `ESP_ERR_TIMEOUT`)
3. Read temperature, pressure, and humidity in one call via `bmp280_read_float()` and validate that no value is NaN

The component reports pressure in pascals; the driver stores hectopascals (`Pa / 100`).

## Measurements

| Measurement | ValueKind | Unit |
|-------------|-----------|------|
| Temperature | `kTemperatureC` | °C |
| Humidity | `kHumidityPercent` | % |
| Pressure | `kPressureHpa` | hPa |

## Notes

- `FORCED` mode means the sensor sleeps between polls and takes a single measurement on demand. This minimizes self-heating at the cost of a brief acquisition delay per poll.
- Oversampling x1 reduces acquisition time at the expense of slightly higher noise.
- If a poll step returns an error, the driver keeps short glitches local and marks the sensor for reinitialization after three consecutive poll failures.
- The driver uses the `esp-idf-lib/bmp280` component (i2cdev-based), the same stack as the other esp-idf-lib sensors. The previous `espressif/bme280` + `espressif/i2c_bus` pair and the `I2cBusManager::getComponentBus()` accessor were removed with this migration.

## Recommended poll interval

Minimum 10 seconds (enforced by the registry). Typical: 10–60 s.

## Component

`esp-idf-lib__bmp280` (managed component; covers both BMP280 and BME280, the driver requires the BME280 chip ID)
